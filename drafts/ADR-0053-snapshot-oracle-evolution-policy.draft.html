§1. Context

folio は自身の canonical spec (design-intent/spec/verification.html) を「手書き」から「機械 SSoT (contract YAML) 生成」へ flip した (folio-nnqh 系)。 flip は canonical HTML を破壊的に生成物へ置換する。 生成物が canonical の機械層 (dual-audience の精密 normative・ADR-0045) を lossless に運ぶことを守るため、 verify-verification.sh は原本 (ORIG) を独立の第 3 者 oracle として生成物と突合する arm を持っていた。

lwhz (folio-lwhz) は、 flip 後 on-disk canonical が生成物そのものになるため ORIG 既定を「flip 前 canonical の不動 snapshot」(spec-origin/verification.origin.html) へ向け、 oracle が「生成物に置換されない独立第 3 者」であり続ける形で 自己比較恒真化を一旦封鎖した。 しかし snapshot 突合には構造的ハザードが残る:

  • 自己比較恒真化の再帰: SPEC_ORIGIN_HTML=生成物 (本番自己比較) を与えると、 相対 parity (c_xref(ORIG) vs c_xref(HTML)) は両辺同値で 任意値 PASS する。 資産を全剥奪した degraded 生成物でも 0==0 で [OK] を出す (lwhz H2 が実証)。
  • 両側同時退行の vacuous PASS: contract と生成物の rich 突合 (§4/§5) は両側が contract 由来ゆえ、 extractor が rich()→plain() へ退行すると contract も生成物も同時に rich を失い、 contract==生成物 は成立したまま canonical との乖離だけが残る。
  • contract (edit-SSoT) の進化: contract が正当に育つ (新 REQ 追加等) と snapshot は古くなる。 snapshot を追随更新すると「flip 前の不動 oracle」という独立第 3 者性が失われ、 更新しないと乖離が gate を赤くする。

user 裁定 (2026-07-18) = 政策 A (bootstrap 退役)。 snapshot 突合は「flip 時 1 回の bootstrap 忠実性 証明」と再定義し以後退役、 恒久防御を canonical / 生成物から独立した三本柱へ移す。

§2. Decision (政策 A)

§2.1 snapshot 突合の退役 (物理定義)

「退役」= ORIG-vs-HTML 相対 parity の退役であって、 snapshot file の物理削除でも fail-closed branch の撤去でもない。 具体的には:

  • §10b の相対 parity 行 (c_xref(ORIG) vs c_xref(HTML) 等) を 撤去する (flip 後 ORIG==生成物 で 自己比較恒真化するため)。
  • §11 round-trip の LEFT を snapshot でなく contract の machine-block から再構成する。
  • 原本不在 fail-closed branch (照合不能 silent skip の回帰 pin) と M15 敵対 case は 存置する。 ORIG は census/round-trip を 消費しないが、 SPEC_ORIGIN_HTML を存在しない path へ向けて gate を silent skip する逃げ道は塞ぐ (存在検査のみ・内容不読)。

§2.2 (a) frozen literal census

期待値を canonical / artifact / 生成物から 導出しない凍結 literal (spec-origin/verification.frozen-census.txt) とし、 measured 側を生成物 HTML (verify の subject) へ固定する。 凍結 literal は両側 (contract / 生成物) と独立ゆえ、 両側同時退行 (collapse) しても frozen 31 vs 生成物 6 で FAIL する。 census 対象: navigable id 総数 + id-rename SET (count 保存 substitution を凍結 SET との comm で捕捉) / a.xref / span.term / ins|del.delta + delta-id SET / escape 済 literal / 人間層 generic inline (code/span の region 別 + 総和) / double-escape / jq -S PRESERVE+mask / JSON-LD folio:stakeholders 型+値。

数字上書き防壁 (census-guard.sh): 凍結 census 値の裸の書き換え (契約変更を伴わない census bump = 退行 launder) を fail-closed で弾く。 (1) provenance sha 整合 = census header の provenance_contract_sha256 == 現 contract sha256。 (2) git-diff coupling = census file が base から MODIFIED なのに contract 未変更なら FAIL。

§2.3 (b) contract 対 machine-block round-trip

§11 round-trip の LEFT を snapshot でも live canonical でもなく contract.machine_preamble[] + sections[].machine_blocks[].html から document 順に再構成し、 RIGHT (生成物 spec-machine-*) と順序付き双方向 diff する。 live canonical repoint は禁止 (demoted vocab の不整合 + 自己比較恒真化)。 本 arm が守るのは assembler バグ (生成物が contract から乖離・silent drop / 順序入替 / cross-section 誤帰属 / 二重 escape) の検出。

★(a)(b) は両側 contract 由来ゆえ両側同時退行で vacuous になりうる → 必ず (c) で塞ぐ。

§2.4 (c) extractor-collapse 敵対 test

extract-verification-spec.sh の人間層 rich() を関数レベルで plain() 相当へ collapse し、 extractor の pre-flip source (snapshot) から re-extract → collapsed contract → in-place generator で assemble → collapsed 生成物。 ① §4/§5 tuple + §11 round-trip の vacuous PASS (contract==生成物・両側同時退行で緑) を実演し、 ② frozen census が collapsed 生成物を独立 anchor として FAIL させる (rich 減少 6<31) ことを red→green で固定する。 ③ SPEC_ORIGIN_HTML= collapsed の本番自己比較でも census が生きる (ORIG 非消費の実証)。 full-repo staging で genuine 再生成する。

§2.5 snapshot file の去就 (admin Leg 0 裁定 2026-07-18)

spec-origin/verification.origin.html は 残置 (撤去しない・git-tracked・bootstrap 記録)。 どの chk も その内容を消費しない (非消費) + selftest で内容 sha256 を pin し cell 内改変を FAIL にする。 provenance: snapshot = git show c705c75:design-intent/spec/verification.html の dl 1.1.0→1.2.0 heal (land commit 83e07b6 = folio-lwhz)。

§2.6 全 flip spec への一般化

政策 A は verification (本 cell 済) / rules (d7bq) / srs-verification (bxpm) / 将来の全 flip spec に一般化する。 各 spec の census/round-trip/collapse arm は同型 (frozen literal + contract round-trip + extractor-collapse)。 跨 cell 順序 (7n17 政策供給 → d7bq/bxpm 消費) と各 spec の凍結定数は admin 領分。

§3. Consequences

  • + 自己比較恒真化 (lwhz H2) の構造的再発を封鎖 (frozen literal は ORIG に依存しない)。
  • + 両側同時退行 (extractor collapse) を独立 anchor + 敵対 test で捕捉。
  • + contract (edit-SSoT) が進化しても oracle の独立第 3 者性ジレンマが消える (snapshot 追随不要)。
  • − 凍結 literal の保守コスト: contract が正当に育つ (新 REQ 等) と census 定数を provenance 付きで 更新する必要がある (census-guard が裸の更新を弾く = 意図的更新を強制)。
  • − census expected と canonical の乖離は「意図的更新漏れ」として FAIL する (fail-closed・望ましい)。
  • 実装主体分離: literal census 更新と extractor-collapse baseline を同一 worker が両方 self-certify しない (CODEOWNERS/branch-protection = reviewer≠committer は Leg B・forge 設定)。

§4. Alternatives Considered

  • 案 B: snapshot 追随更新 — contract 進化のたび snapshot を再生成。 却下: oracle の「生成物に置換 されない独立第 3 者」性が失われ、 snapshot が生成 path に依存する (自己比較恒真化の温床が戻る)。
  • 案 C: census expected を contract meta 宣言 — contract に期待件数を宣言。 却下: contract は edit-SSoT (artifact) ゆえ、 そこから期待を導出すると両側同時退行で vacuous-PASS が再導入される。
  • 案 D: live canonical repoint — round-trip LEFT を live canonical へ。 却下: flip 後 canonical== 生成物 で自己比較恒真化 + demoted vocab 不整合。
