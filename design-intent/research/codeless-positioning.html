folio コード無しプロジェクトへの射程 (codeless positioning)

v1.0.0 · status: active · folio 文書規律をコード無しプロジェクト (政策・ガバナンス・標準化 等) へ拡げる位置づけの明文化 (P-7 探索・方向のみで決定しない)

§0. 要旨

folio の文書規律エンジンは設計上すでにコード非依存であり、「コードのある SW プロジェクト」への限定は SRS-pack 固有の写像にすぎない。本 note は folio の射程を「あらゆる構造化知識プロジェクト (政策・ガバナンス・標準化・研究プログラム・事業計画・法務枠組 等)」へ拡げる方向の明文化を行う。P-7 探索領域の作法に従い、ここでは決定しない — scope を silently 拡大せず、将来の判断材料 (grill / ADR 起票) の grounding とする。

骨子は doctype-coverage-audit §4 (doctype-completeness-audit wf_8e16a043 の codeless_positioning 出力) を展開したもの。起票 = bd folio-dxq (user grill 2026-06-24 発)。

§1. 動機

folio の文書型 (SRS / ADR / research / principle / spec / architecture-description / glossary / vision / testcases / datamodel / interface) は本質的にコード非依存である。さらに folio の中核価値である dual-audience (非エンジニア + 機械の両対応) は、混在読者が常態のコード無しプロジェクトでこそ価値が増す: SW プロジェクトでは「非エンジニア読者」は周縁だが、政策文書・ガバナンス憲章・標準文書では専門家 vs 市民/議員/監査人の混在が読者構造の本体であり、平易層と精密層の 1-DOM 共存 (co-author) がそのまま効く。

§2. 核心命題 — engine のコード非依存性 (verified)

core の照会 graph が使う抽象ロール集合は GRAPH_ROLE_ALLOWLIST = claim|rationale|exploration|principle|verification|implementation (.claude-plugin/design-system/generator/lib/graph-common.sh) であり、「コード」概念を含まない (2026-07-12 実コード再確認済)。「実装 = コード」は SRS-pack 固有の写像にすぎず、ADR-pack は implementation ロールを「実装方式 (非コード)」へ既に写像している (audit wf_8e16a043 確定)。つまり engine の機械層 (floor gate / graph 検査 / round-trip) はドメイン語彙に依存せず、写像の付け替えは pack 層で完結する。

§5. 橋頭堡戦略

第一橋頭堡 = principle/constitution pack: 要件索引型を脱した実証済 pack であり、公共政策の基本方針・ガバナンス憲章は principle 型 (動かせない約束の宣言 + tier + amendment) にそのまま写る。gate I (非エンジニア読了) を既に達成している (audit §4 の確定)。第二 = architecture-description pack (ADR-0046): 要件型を脱した初の記述型 doc-type で、制度・組織の「何がどう組み合わさって動くか」に写る。

§6. 未解決 (open questions — 本 note は決定しない)

  • 純記述型 doc-type の floor の厚み (最大の不確実点): EARS が乗らない記述型では機械検査可能な構造が薄く、ceiling (LLM reviewer) 依存が増して機械保証強度が落ちる。floor をどこまで厚くできるかは記述型 pack (arch/vision/datamodel) の実績蓄積で判断する。
  • HOW-outside の「HOW」再定義: 施行手順・運用細則を design-intent の外に置く境界語彙をドメイン別にどう言語化するか。
  • implementation ロールの表示語彙: 機械層 (GRAPH_ROLE_ALLOWLIST) は不変のまま、pack 表示層でロール名をドメイン語 (施行/運用) へ訳すだけで足りるか。
  • dogfood 経路: 非 SW ドメインの実 consumer で歩ける website + validate + ceiling を通す検証をどこで行うか (実プロジェクト連携 or デモ contract)。
