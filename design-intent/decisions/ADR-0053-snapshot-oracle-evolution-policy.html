ADR-0053 — snapshot oracle 進化政策 A

Status: accepted · Date: 2026-07-19 · folio v1.2.0 · folio 自身の canonical spec が「手書き」から「機械 SSoT 生成」へ flip した後、 生成物の機械層 fidelity を守る snapshot oracle 突合 arm が 自己比較恒真化 (flip 後 ORIG==生成物 で任意値 PASS) の再発ハザードを持つ。 政策 A (user 裁定 2026-07-18) はこの snapshot 突合を「flip 時 1 回の bootstrap 忠実性証明」に退役させ、 恒久防御を (a) frozen literal census (b) contract 対 machine-block round-trip (c) extractor-collapse 敵対 test の三本柱へ移す。 snapshot file (spec-origin/verification.origin.html) は bootstrap 記録として残置し、 どの chk も その内容を消費しない (非消費・存在検査のみ fail-closed)。 内容の完全性は git 管理 (tracked) と review が担う。 verification 済 / rules (d7bq) / srs-verification (bxpm) / 将来の全 flip spec に一般化する。 ★2026-07-19 user 文案承認済 — status = accepted。

§1. Context

folio は自身の canonical spec (design-intent/spec/verification.html) を「手書き」から「機械 SSoT (contract YAML) 生成」へ flip した (folio-nnqh・folio-lwhz)。 flip は canonical HTML を破壊的に生成物へ置換する。 生成物が canonical の機械層 (dual-audience の精密 normative・ADR-0045) を lossless に運ぶことを守るため、 verify-verification.sh は原本 (ORIG) を独立の第 3 者 oracle として生成物と突合する arm を持っていた。

flip 後は on-disk canonical が生成物そのものになるため、 ORIG 既定は「flip 前 canonical の不動 snapshot」(spec-origin/verification.origin.html) へ向けられ、 oracle が「生成物に置換されない独立第 3 者」であり続ける形で 自己比較恒真化は一旦封鎖された (folio-lwhz)。 しかし snapshot 突合 (= snapshot oracle の ORIG-vs-HTML 比較 arm) には構造的ハザードが残る:

  • 自己比較恒真化の再帰: SPEC_ORIGIN_HTML=生成物 (本番自己比較) を与えると、 相対 parity (c_xref(ORIG) vs c_xref(HTML)) は両辺同値で 任意値 PASS する。 資産を全剥奪した degraded 生成物でも 0==0 で [OK] を出す (folio-lwhz で実証)。
  • 両側同時退行の vacuous PASS: contract と生成物の rich 突合 (§4/§5) は両側が contract 由来ゆえ、 extractor が rich()→plain() へ退行すると contract も生成物も同時に rich を失い、 contract==生成物 は成立したまま canonical との乖離だけが残る。
  • contract (edit-SSoT・ADR-0051) の進化: contract が正当に育つ (新 REQ 追加等) と snapshot は古くなる。 snapshot を追随更新すると「flip 前の不動 oracle」という独立第 3 者性が失われ、 更新しないと乖離が gate を赤くする。

user 裁定 (2026-07-18) = 政策 A (bootstrap 退役)。 snapshot 突合は「flip 時 1 回の bootstrap 忠実性 証明」と再定義し以後退役、 恒久防御を canonical / 生成物から独立した三本柱へ移す。

§2. Decision (政策 A)

§2.1 snapshot 突合の退役 (物理定義)

「退役」= ORIG-vs-HTML 相対 parity の退役であって、 snapshot file の物理削除でも fail-closed branch の撤去でもない。 具体的には:

  • §10b の相対 parity 行 (旧称「ORACLE parity」・c_xref(ORIG) vs c_xref(HTML) 等) を 撤去する (flip 後 ORIG==生成物 で 自己比較恒真化するため)。
  • §11 round-trip の LEFT を snapshot でなく contract の machine-block から再構成する。
  • 原本不在 fail-closed branch (live gate の「ORACLE 存在 pin (bootstrap 記録)」・照合不能 silent skip の回帰 pin) と M15 敵対 case は 存置する。 ORIG は census/round-trip を 消費しないが、 SPEC_ORIGIN_HTML を存在しない path へ向けて gate を silent skip する逃げ道は塞ぐ (存在検査のみ・内容不読)。

§2.2 (a) frozen literal census

期待値を canonical / artifact / 生成物から 導出しない凍結 literal census (spec-origin/verification.frozen-census.txt) とし、 measured 側を生成物 HTML (verify の subject) へ固定する。 凍結 literal は両側 (contract / 生成物) と独立ゆえ、 両側同時退行 (collapse) しても frozen 31 vs 生成物 6 で FAIL する。 census 対象は navigable id 総数と id-rename SET (count 保存 substitution を凍結 SET との comm で捕捉)・機械層 rich 資産 (a.xref / span.term / delta) の件数と SET・ escape/二重 escape 等の表現健全性に及ぶ (decision 時点の scope)。 全次元の網羅列挙は凍結 census file と verify-verification.sh が保持し、 contract の成長に応じて provenance 付きで更新する (§3)。

数字上書き防壁 (census-guard.sh): 凍結 census 値の裸の書き換え (契約変更を伴わない census bump = 退行 launder) を fail-closed で弾く。 (1) provenance sha 整合 = census header の provenance_contract_sha256 == 現 contract sha256。 (2) git-diff coupling = census file が base から MODIFIED なのに contract 未変更なら FAIL (初回 freeze の ADDED は coupling 免除)。

§2.3 (b) contract 対 machine-block round-trip

§11 round-trip の LEFT を snapshot でも live canonical でもなく contract.machine_preamble[] + sections[].machine_blocks[].html から document 順に再構成し、 RIGHT (生成物 spec-machine-*) と順序付き双方向 diff する。 live canonical repoint は禁止 (demoted vocab の不整合 + 自己比較恒真化)。 本 arm が守るのは assembler バグ (生成物が contract から乖離・silent drop / 順序入替 / cross-section 誤帰属 / 二重 escape) の検出。 本節は ADR-0045 (機械層 round-trip) の LEFT source 定義を改訂する。

★(a)(b) は両側 contract 由来ゆえ両側同時退行で vacuous になりうる → 必ず (c) で塞ぐ。

§2.4 (c) extractor-collapse 敵対 test

extract-verification-spec.sh の人間層 rich() を関数レベルで plain() 相当へ collapse し、 extractor の pre-flip source (snapshot) から re-extract → collapsed contract → in-place generator で assemble → collapsed 生成物。 ① §4/§5 tuple + §11 round-trip の vacuous PASS (contract==生成物・両側同時退行で緑) を実演し、 ② frozen census が collapsed 生成物を独立 anchor として FAIL させる (rich 減少 6<31) ことを red→green で固定する。 ③ SPEC_ORIGIN_HTML= collapsed の本番自己比較でも census が生きる (ORIG 非消費の実証)。 full-repo staging で genuine 再生成する。

§2.5 snapshot file の去就 (裁定 2026-07-18)

spec-origin/verification.origin.html は 残置 (撤去しない・git-tracked・bootstrap 記録)。 どの chk も その内容を消費しない (非消費)。 検査は存在 pin のみ fail-closed で行い、 内容の完全性は git 管理と review が担う。 provenance: snapshot = git show c705c75:design-intent/spec/verification.html の版番号 (dl 内 dd) 1.1.0→1.2.0 置換 heal (land commit 83e07b6 = folio-lwhz)。

§2.6 全 flip spec への一般化

政策 A は verification (適用済) / rules (folio-d7bq) / srs-verification (folio-bxpm) / 将来の全 flip spec に一般化する。 各 spec の census/round-trip/collapse arm は同型 (frozen literal + contract round-trip + extractor-collapse) で、 凍結定数 (census) は spec ごとに独立に freeze する。

§3. Consequences

  • + 自己比較恒真化 (folio-lwhz で実証) の構造的再発を封鎖 (frozen literal census は ORIG に依存しない)。
  • + 両側同時退行 (extractor collapse) を独立 anchor + 敵対 test で捕捉。
  • + contract (edit-SSoT) が進化しても oracle の独立第 3 者性ジレンマが消える (snapshot 追随不要)。
  • − 凍結 literal census の保守コスト: contract が正当に育つ (新 REQ 等) と census 定数を provenance 付きで 更新する必要がある (census-guard が裸の更新を弾く = 意図的更新を強制)。
  • − census expected と canonical の乖離は「意図的更新漏れ」として FAIL する (fail-closed・望ましい)。
  • 常設 enforcement: 三本柱の敵対 suite (COLLAPSE / M-SELFCMP / F19 census 群) と数字上書き防壁 (census-guard) は CI の blocking gate として常設実走される (drift gate は fresh 再生成も同時 collapse するため 両側同時退行を構造的に捕捉できず、 代替にならない)。
  • 実装主体分離: literal census 更新と extractor-collapse baseline を同一の主体が両方 self-certify しない (reviewer≠committer の分離は CODEOWNERS/branch-protection 等の forge 設定で担保する)。

§4. Alternatives Considered

  • 案 B: snapshot 追随更新 — contract 進化のたび snapshot を再生成。 却下: oracle の「生成物に置換 されない独立第 3 者」性が失われ、 snapshot が生成 path に依存する (自己比較恒真化の温床が戻る)。
  • 案 C: census expected を contract meta 宣言 — contract に期待件数を宣言。 却下: contract は edit-SSoT (artifact) ゆえ、 そこから期待を導出すると両側同時退行で vacuous-PASS が再導入される。
  • 案 D: live canonical repoint — round-trip LEFT を live canonical へ。 却下: flip 後 canonical== 生成物 で自己比較恒真化 + demoted vocab 不整合。
