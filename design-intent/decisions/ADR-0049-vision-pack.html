§1. Context

engine epic folio-0dv は folio の文書規律を一般化した汎用文書生成エンジンを構築する。 その sub-epic folio-c5r は「任意プロジェクト向けの完全な文書一式」を被覆する roadmap である。 ADR-0046 が要件索引型を脱した初の記述型 doc-type = architecture-description (構造の WHAT) を追加した。 完全 doc-suite にはもう一つ、 索引型でも構造記述でもない層 — 「なぜ作るか」を描く vision (ビジョン) — が欠けていた。

gap — 「なぜ作るか」層が engine に欠けている。 SRS は振る舞いの WHAT、 architecture は構造の WHAT、 ADR は個別判断の WHY を記録するが、 プロジェクト全体がどの状態を目指し (北極星)・何を成功と測り (目標・成功基準)・どの方向の機能で実現するかを高度から束ねる文書は無かった。 vision はこの最上流の「なぜ」を担い、 下位の SRS/arch/ADR は最終的にこの意図へ遡れるようにする。

framing — vision は「なぜ作るか」であって「何を作るか」でない。 vision と SRS の二重記述 (no-restate 問題) が最大の設計不確実点だった。 vision は北極星・why-it-matters・目標という別の高度を描き、 具体の要件・受入基準・アクター役割は SRS の領分ゆえ、 vision はそれらを照会するだけで再掲しない (案A・§2.3)。 goals (vision の測定物差し = 経営がいつ「成功」と言えるか) と acceptance criteria (SRS の機械検証可能な合格条件) は高さの違う 2 つの物差しであり同一物の再掲でない、 という区別が no-restate の核心である。

vision も記述型 pack ゆえ、 設計 grill (2026-07-04) は ADR-0046 と同じく demo-walk-first で進めた — opus でモックアップを生成し :8729 で walk し、 反応で 7 章粒度・id 5 種の切り方・北極星文の読み味を確定してから本物の決定的 pack を構築した。 clinic 診療予約 vision を母体 (instance#1) に本物 pack を構築・検証し、 本 ADR はその実装 + 検証 + land 後の forward decision を記録する。 build に先立ち、 arch pack の band 見出しに残っていた instance 固有 hardcode (件数/ドメイン文言) を contract 化し genuine-shape floor を硬化する folio-bhe を独立先行 land した (vision assembler が同じ罠を掘らない予防規律)。

§2. Decision

§2.1 schema (Pichler 骨 + Wiegers 選抜の lean hybrid・7 章)

vision pack は Pichler Product Vision Board の lean な骨 (北極星 / 対象 / ニーズ / 機能 / 価値) に Wiegers Vision&Scope の測定可能要素 (目標 + 成功基準 + 非目標) を選抜移植した lean hybrid を schema に採る (arc42+C4 を採った arch と同じ「業界の骨を選抜合成する」様式)。 章立ては固定 7 章: 北極星 / 解くに値する問題 / 関係者 / 目標+成功基準 / 主要機能の方向 / リスク+非目標 / 指針価値。 id 付き離散 node は 5 種: ST (関係者) / G (目標) / SC (成功基準) / F (機能の方向) / R (リスク)。 arch と同じく固定章の集合が floor の検査単位を与える (§2.2)。 vision は用語集章を持たない — 高度な narrative ゆえ専門語は本文で括弧併記し、 用語 SSoT は下位の索引型 (SRS 以下) が担う。 North Star Framework の metric 駆動を採らない: 質的 vision (北極星 folio-7wn 自身が定量 metric を持たない反例) を排除するため、 成功基準は任意の測定物差しに留め metric を必須化しない。

§2.2 floor 三本柱の流用 + vision 固有の件数 guard 不要化

vision の floor は ADR-0046 の三本柱をそのまま流用する: (a) 照会 graph 整合 (features→SRS 充足照会が実在 FR を role 通り指す・verify_cross_doc_refs 流用) / (b) navigable id アンカー (ST/G/SC/F/R の各 node に安定 id を emit・案A 照会を人間が辿れる) / (c) 固定 7 章 + 各章の必須要素存在。 加えてgenuine-shape 構造不変条件 (folio-bhe 教訓: band/h2 を要素単位・case-insensitive・attribute-tolerant に数え decoy 見出しを封鎖) と可視テキスト fabrication-free (属性 intact でも可視だけ捏造する fail-open を全 node で封鎖) を課す。

★arch の件数 guard (band_numchk / 全角 / 不可視文字) は vision に不要。 arch の band 見出しは instance 固有の件数 (「6 つの部品」) を持ち、 その count fabrication を封鎖する guard が要ったが、 vision の 7 つの band 見出しは全て pack 不変 (件数・ドメイン非依存の汎用フレーズ) ゆえ literal pin で足りる。 章数 (7) は verify の期待見出し配列長から単一 SSoT 導出し、 magic「==7」を書かない (folio-bhe ceiling が arc42 専用「==8」の pack 流用破綻を反面教師として教えた)。 cover の構成件数 (目標 3 / 機能 4 等) は contract 配列長から導出し instance hardcode しない (folio-bhe 予防規律を最初から適用)。

§2.3 自前 inline principle 自己終端 + vision→SRS backward 照会

vision は照会 graph の終端を自前の inline principle (指針価値・例 PRIN-PATIENT-TRUST) で持ち、 自己終端する。 母体 clinic は constitution をゼロ生成する (index 型 suite ゆえ) ため外部 principle へ forward できず、 終端手段は inline principle か SRS 連鎖の 2 択に絞られ、 arch 先例 (inline) に倣い inline principle に確定した。 vision→SRS の照会 edge は backward (arch→SRS の完全ミラー): reachability は SRS→vision となり、 vision の backward edge がedgeless な SRS へ終端到達路を供給する (SRS は自前終端を持たず、 arch と vision の 2 経路から終端到達する冗長構造)。 ★inline principle のgenuine 性 (グラフ充足のための作文でなく本物の判断規則か = 北極星の言い換えでなくトレードオフ時にどちらへ倒すかを実際に決める規則か) は機械 floor で裁けず、 ceiling の明示的検査観点として課す (folio-5se の vision 専用 fidelity lens へ焼き込む)。

§2.4 Moore pitch opt-in + 目標ツリー図 optional (必須化しない)

北極星文は自由叙述を既定とし (捏造/歪みは ceiling が検査)、 Moore の elevator-pitch 文法 (対象顧客 / ニーズ / カテゴリ / 独自価値 / 競合との違い) は任意追加 slot (opt-in) とする — contract に pitch がある時だけ穴埋め表を描画し、 各穴と本文の章の対応を floor が内部照会 anchor で検査する。 目標ツリー図 (北極星→目標→成功基準の mermaid) もoptional — ある時だけ描画忠実性を検査する。 いずれも必須化しない: 質的 vision (metric 無しの folio-7wn が反例) を排除しないため。 opt-in 要素の不在でも floor が PASS することを敵対テストで pin する。

§2.5 横断原則 (core 無改変 / clinic 先 / glossary 章なし)

  • ★core (lib/ + inject-prose.sh) 無改変 — 記述型 2 例目も byte-identity で挿さる。 ADR-0046 §2.4 の core 抽出完了 doctrine が 2 例目でも保たれ、 rule-of-three (pack 追加は core 不変) を継続実証。 pack 追加物は contract YAML + assemble-vision.sh + rolemap + verify-vision.sh + prose manifest + test-adversarial-vision.sh + CONTENT_LEAVES[vision] 登録 のみ。 記述型共通 helper の抽出は見送る (rule-of-three の 3 例目で別途判断)。
  • clinic 先 → folio-self vision は後 — 境界の明確な clinic 診療予約 vision (instance#1) で assembler を先に証明し、 最難の meta × 記述型である folio-self vision (北極星 folio-7wn 自身の self-host) は後の self-dogfood 段階で instance#2 として回収する (folio-qvv・arch の folio-self-spec 後回しと同型)。
  • glossary 章なし — vision は高度 narrative ゆえ用語集章を持たず、 専門語は本文で括弧併記する (用語 SSoT は下位索引型が担う)。 verify_core_chrome の glossary chrome 突合が空 glossary で mikefarah yq の collect+@tsv quirk (空入力 phantom 行) に当たるため、 vision verify は cover-head/approval/reader-chip の chrome 検査を core 無改変のまま inline (glossary 4 検査を除いた faithful subset) する。

§3. Consequences

  • 得るもの: 完全 doc-suite に「なぜ作るか」の最上流層が加わり、 下位の SRS/arch/ADR が最終的に vision の意図 (北極星・指針価値) へ遡れる。 案A で vision が SRS を再掲せず照会で繋がり (no-restate = drift 源排除)、 vision の backward edge が edgeless な SRS へ終端到達路を冗長供給する。 記述型 2 例目でも floor 三本柱が流用でき、 engine core が無改変で保たれ engine 汎用性の射程が「なぜ作るか」層へ広がる。 opt-in 設計 (Moore pitch / 目標ツリー) で質的 vision と定量 vision の双方を排除しない。
  • 払うもの: 意味 fidelity は ceiling 前提 — 北極星文の genuine 性・inline principle が作文でないこと・章リードの件数 (「3 つの目標」等) が配列長に忠実かは機械 floor で裁けず、 vision 専用 ceiling agent (folio-5se) の制度化を前提とする。 可視 exotic encoding での件数捏造等も machine/LLM 境界ドクトリン上 ceiling 領分 (floor は不可視クラス + algorithmic のみ)。 pack ごとに contract を維持する。
  • ADR-worthiness (rules §10.3): hard-to-reverse (7 章 schema・floor 三本柱流用・自己終端モデル・案A は consumer が vision doc を生成し始めると転換が高コスト) / surprising (索引型でも構造記述でもない第三の記述型 / vision が edgeless SRS へ終端路を供給する backward edge / metric 必須化を質的 vision 反例で排除) / real-trade-off (inline 自己終端 vs 外部接地・opt-in vs 必須・no-restate 案A vs 転写・metric 駆動 vs 質的 の 4 種以上の実トレードオフ) の 3 条件を満たす。

§4. Alternatives

  • (終端) 外部 principle へ forward 接地する — 不採用。 母体 clinic は constitution ゼロ生成ゆえ外部 principle が存在せず forward 不能。 自前 inline principle で自己終端する (arch 先例と同型)。
  • (照会) vision が SRS の要件/受入基準を inline 転写する — 不採用。 SRS が既に SSoT を持ち二重保持 = drift 源。 vision は北極星/why の別高度に徹し、 具体は SRS へ照会する (案A)。 goals (経営の物差し) と acceptance (機械検証条件) の高さの違いが再掲でないことの根拠。
  • (schema) North Star Framework の metric 駆動を必須化する — 不採用。 質的 vision (定量 metric を持たない北極星 folio-7wn が反例) を排除してしまう。 成功基準は任意の測定物差しに留め metric を必須化しない。
  • (opt-in) Moore pitch / 目標ツリー図を必須化する — 不採用。 上と同根で質的 vision を排除する。 opt-in / optional とし、 不在でも floor PASS を敵対テストで pin する。
  • (母体) folio-self vision を先に構築する — 不採用。 meta × 記述型は最難で 2 例目段階で de-risk できない。 clinic で証明してから folio-self vision を後の self-dogfood 段階で self-host する (folio-qvv)。
