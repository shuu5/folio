§0. Reader's Guide

この spec は、 folio の generator が機械 SSoT (contract + prose YAML) から生成する SRS プレゼン HTML が「完成した (GREEN)」と言える条件を定める。 決定的で blocking な floor と LLM の ceiling の二層で、 floor 単独では GREEN を宣言しないのが要。

読み方: §1 が機械/LLM 検証境界 (何を決定的 floor が裁き、 何を LLM ceiling が裁くか) を宣言し、 §2 がその境界に沿って done-condition を REQ-VER-024〜030 で形式化する。 §3 が検証被覆 (RTM)、 §4 が参照。 REQ-VER-001〜023 / REQ-NAV-001〜007 (folio 自身の verification) は姉妹 spec verification.html にある。

§1. 機械/LLM 検証境界と done-condition モデル

機械 SSoT から生成した SRS プレゼン HTML の完成判定を、 決定的で blocking な floor と LLM の ceiling の二層で定義する (REQ-VER-024〜030、 SRS 部品 taxonomy §5)。 機械/LLM 検証境界: 件数・構造・render・構成同一性など算術的に自明なものだけを floor が blocking で裁き、 自由文の捏造・可読性・意味カバレッジは LLM の ceiling (gate J / I / K) が裁く。 一次根拠は fabrication-free-by-construction (rules §12・構造捏造は構成上不可能) ゆえ、 静的 ban 群は非 blocking の warn 級 backstop に留め、 floor 単独で GREEN を宣言しない。

以下は folio 自身の spec 検証 (verification.html §3.6 / §3.8) と異なり、 consumer が機械 SSoT から生成する SRS プレゼン HTML の done-condition を定義する (design-system generator .claude-plugin/design-system/generator/ が実装)。 設計 SSoT は SRS 部品 taxonomy §5 (二層判定式 floor + ceiling)、 生成方式は ADR-0042 (ハイブリッド = 構造決定的・prose のみ opus) / ADR-0041。 conformance は generator-local の test-adversarial.sh + render-gate-srs.py --selftest (sandbox scenarios でなく generator-local + CI dogfood — 生成物向けゆえ consumer の folio validate には入れない)。 本 spec は taxonomy §5 で設計済みの二層モデルを REQ-VER 形式で形式化する (新規 ADR を要さない)。 機械/LLM 検証境界: 自由文の意味的忠実性 (契約への忠実さ・捏造・矛盾・可読性) は決定的アルゴリズムで判定不能ゆえ、 機械 floor は algorithmic に自明なもの (件数・id・集合・派生・構造の存在/完全性・幾何 render 健全性) のみを blocking で裁き (escape 健全性の検査は warn 級 backstop の領分)、 意味検証は独立コンテキストの LLM reviewer を複数束ねる ceiling (taxonomy §5.3 gate I/J/K) が担う (確信は reviewer 数と敵対的突合で調整・別建ての決定的安全網を後付けしない)。 その一次根拠 = fabrication-free-by-construction (rules §12 が WHAT の SSoT・構造捏造は構成上排除済み) ゆえ、 機械 census (全列挙 backstop) が捏造を再検査するのは重複検査であり、 静的 hidden-render ban 群 (REQ-VER-024) の意味権威は ceiling gate I/J にあり、 これら決定的機構は honest-bug を実捕捉する warn 級 backstop (非 blocking) である。 blocking の部品件数照合は census-count arm (REQ-VER-024 blocking arm・source DOM の静的件数 ↔ contract 期待件数・render 不要) が、 post-build 改変の検出は構成同一性 arm (REQ-VER-030) が担う (機構と検出完全性の論証は同 record が SSoT)。 census closure 語彙の全単射 (REQ-VER-029) は本境界下では語彙鮮度の floor である (census 消費の基盤ではない)。 各 REQ-VER の gate 割当・blocking arm と warn 級 backstop の区分は本 spec が SSoT。

§2. done-condition REQ (REQ-VER-024〜030)

生成 SRS の done-condition を 5 REQ で形式化する (REQ-VER-024〜030・027/028 は欠番)。 各 REQ が §1 の境界のどこ (blocking floor / warn 級 backstop / ceiling) に属すかを、 各 REQ の essence と machine 部の双方に明記する。

REQ-VER-024 Event folio verify-srs <html> <contract> は生成 SRS の決定的 floor を検査する: blocking arm = gate A–E,G,H + visual-first + census-count (部品件数の静的 DOM 照合)。 静的 hidden-render ban 群と visual-deception ban は fabrication-free-by-construction (rules §12) の脅威向けwarn 級 backstop (非 blocking・意味権威は ceiling gate J)。 ★blocking arm 全 PASS でも CEILING=PENDING を返し floor 単独 GREEN を禁じる (手編集後も再検証可・render/構成同一性/ceiling は 025/030/026、 ban 群一覧と詳細は machine 部)。

REQ-VER-024: WHEN the folio verify-srs <generated.html> <contract.yaml> command runs (CLI 引数順 = <html> <contract>、 html=主対象), it SHALL check the deterministic floor of a generated SRS presentation (taxonomy §5.2 gate A–E,G,H + visual-first) over the (contract, html) pair alone (manifest 不要 = 成果物入力ゆえ手編集後も再検証可), flagging with non-zero exit: gate A — 各 MUST 部品 (S5 凍結 required-existence 集合: doc-cover-band / chapter-deck-band / section-lead-callout / scope-summary-panel / actor-stakeholder-table / source-trace-origin / requirement-matrix-table / ears-requirement-row / priority-badge / nfr-hero-metrics / nfr-metrics-table / acceptance-criteria-checklist / rtm-collapse / constraint-callout / glossary-term-table / fidelity-sync-meta / requirement-type-color-tokens) が data-component 属性で各 ≥1 (条件付き MUST = MUST-when-applicable は凍結集合外); REQ-VER-025 Event gate F (render 健全性、 render-gate-srs.py) は生成 SRS を light/dark × 3 viewport で実 render し、 WCAG AA low-contrast / horizontal-overflow / component-overlap を検出する (fail-closed)。 重い playwright ゆえ renderer 在環境で実行し、 不在は honest SKIP (PASS と詐称しない)。 描画後 content の意味 fidelity は ceiling gate J・post-build 改変は REQ-VER-030 の領分 (検出器・定数は machine 部)。

REQ-VER-025: WHEN gate F (render 健全性、 render-gate-srs.py、 taxonomy §5.2) runs against a generated SRS presentation, it SHALL render the artifact in headless chromium at light / dark の両 prefers-color-scheme × 3 viewport (375 / 768 / 1280) and probe the post-render DOM, flagging with non-zero exit three classes: (1) low-contrast — 各 text 要素の文字色と実効背景の WCAG 2.1 コントラスト比が AA 未満 (通常 4.5:1 / 大 text 18pt=24px or 14pt-bold=18.66px は 3.0:1)。 実効背景は祖先を遡って不透明 background-color を底に半透明 layer を alpha 合成し、 gradient 背景は各レイヤーの停止色を抽出して下から alpha 合成した候補集合の worst-case (最小コントラスト) 停止で判定する (薄い勾配上の白文字を素通りさせない)。 色は 1×1 canvas で任意 CSS 色 (oklch / lab / hsl / hex / rgb 各構文) を sRGB へ解決する; 停止色を抽出できない真の image (url()) のみ skip し件数を disclose する; (2) horizontal-overflow — document.scrollWidth > clientWidth + 2px の意図しない横スクロール (overflow-x:auto の内部 scroll container は document に寄与しないため発火しない); (3) component-overlap — [data-component] が別の可視 block 要素 (素の div/li 等を含む広い集合・包含/inline は除外) と面積比 > 0.15 で矩形交差 (絶対配置・負 margin の崩れ + 非コンポーネント装飾の被さりを捕捉)。 It SHALL fail-closed: 検査対象 text が 1 つも無い (textChecked == 0) = render 破綻として「clean」でなく FAIL に倒す。 重い playwright 検査ゆえ folio verify-srs は renderer 在環境でのみ gate F を実行し、 不在環境では honest SKIP (RESULT を「gate F 未実行・floor 不完全」と明示し PASS と詐称しない); SRS_SKIP_RENDER=1 で bash-only floor に外せる。 幾何定数 (横溢れ許容 2px / overlap 面積比 0.15) は REQ-VER-022 の probe.js (ADR-0037) の値を複製する (drift は test-adversarial.sh A35 が検知)。 conformance は render-gate-srs.py --selftest (fixture 10 本 / case 17: low-contrast/overflow/component-overlap の kind 完全一致発火 + dark-only 崩れ + gradient×dark + url-image skip + viewport plumbing + fail-closed) + CI render-gate job (dogfood SRS を build→gate F、 sandbox 被覆外の CI-only)。 gate F は描画の見た目崩れに限り、 描画後 content の意味 fidelity は ceiling gate J の領分・post-build 改変は REQ-VER-030 (構成同一性) が byte 検出する。 scope は ADR-0037 (検出器・二層) + ADR-0041 (dark-contrast 崩壊型の検出を含む) で trace。

REQ-VER-026 Ubiq. 生成 SRS が GREEN ⟺ blocking floor 全通過 (REQ-VER-024 の blocking arm + 025 render 健全性 + 030 構成同一性) AND ceiling 合格 (gate I 可読性 + gate J 捏造 + gate K 意味カバレッジ)。 verify-srs は floor 通過時に CEILING=PENDING を返して floor 単独 GREEN を機械的に禁止し、 静的 ban 群は warn 級 backstop ゆえ GREEN 判定に含めない。 ceiling は LLM で非決定的、 floor は決定的・blocking の二層 (北極星 = gate I の非エンジニア可読性)。

REQ-VER-026: A generated SRS presentation SHALL be considered GREEN if and only if both layers pass: (floor) 全 blocking floor gate が PASS (REQ-VER-024 の folio verify-srs 決定的 floor の blocking arm 〔gate A–E,G,H + visual-first + census-count = 部品件数の静的 DOM count 照合〕 ∧ REQ-VER-025 の gate F (render 見た目崩れ) ∧ REQ-VER-030 の構成同一性 (機械 SSoT からの決定的再組立との byte 同一性)。 静的 hidden-render ban 群 (REQ-VER-024) は warn 級 backstop ゆえ GREEN 判定の blocking floor に含めない — その意味権威は下記 ceiling gate I/J; 測定系 tool-integrity error 〔render 破綻・再組立入力欠落等〕 は gate 判定と別軸で非零 exit する 〔測定不能を clean と詐称しない〕) AND (ceiling) 意味判定の 3 lens が合格 (taxonomy §5.3 gate I = persona-walk-srs agent 〔可読性の意味権威〕、 gate J = fidelity-srs agent 〔捏造の意味権威〕、 gate K = completeness-critic-srs agent 〔意味カバレッジ完全性〕)。 It SHALL NOT declare GREEN on floor pass alone — folio verify-srs が floor 通過時に CEILING=PENDING (exit 0 ≠ GREEN) を返すことで「floor 単独 GREEN 禁止」を機械担保する (taxonomy §5.1 判定式、 ADR-0040 の長さ Goodhart 再発防止)。 gate I (persona walk) = 非エンジニア persona が生成 SRS を index から歩き「何が要件か・なぜ要るか・どう検証されるか」を頑張れば読めるか (専門エンジニアがなんとか読める水準では不合格 = ADR-0041 北極星); gate J (fidelity) = 生成 HTML が機械 SSoT contract の正確な要約か — 情報落ち / 歪み / 捏造 (AI 捏造 RTM 行・SSoT 外の rationale 作文等) が無く、 派生ビュー (plain-language-term-inline) が SSoT 一致、 要件間 consistency (矛盾) も surface。 3 gate は agents/persona-walk-srs.md / agents/fidelity-srs.md / agents/completeness-critic-srs.md として常設し、 spec 用 Phase F の spec-review-* agent と同型の LLM review (read-only・構造化 findings)。 ceiling は LLM ゆえ非決定的 = CI で blocking しない (ADR-0028 の二層 enforcement と同型: floor=機械/blocking + ceiling=LLM/advisory)。 conformance: 二層 invariant (floor PASS ≠ GREEN) は決定的ゆえ test-adversarial.sh A22 (健全 artifact に verify-srs が CEILING=PENDING を返す = GREEN を宣言しない) が固定し、 ceiling agent は fidelity が SSoT 外の捏造 RTM 行を検出する型 (taxonomy §5.3 / ADR-0041 §2.5) を実装する。 scope は taxonomy §5.1 / §5.3 + ADR-0041 §2.5 (persona walk + fidelity = 原 2-gate co-equal; completeness = 第 3 翼 gate K の定義元は taxonomy §5.3) で trace。

REQ-VER-029 Event verify-census-vocab.sh (決定的 CI floor) は closure 語彙 SSoT (srs.census-vocab.yaml) と assembler の emit 集合の bijection (emit == vocab) を assert し、 部品の追加・改名・削除での語彙未更新を非ゼロ exit で強制する。 捏造検出の意味権威は ceiling gate J にあるため、 本 gate は語彙鮮度の floor のみを担い census closure 基盤を消費しない (SSoT 配線・graph 非破壊は machine 部)。

REQ-VER-029: WHEN the verify-census-vocab.sh deterministic CI floor runs, it SHALL extract the set of data-component and data-prose-slot tokens emitted by assemble-srs.sh (SRS-pack 固有 emitter) と lib/common.sh (core chrome emitter) — 両 file を走査し、 lib/common.sh が perl 文字列内で backslash-escape する data-component=\"…\" 形も拾う robust 抽出 (SRS grep だけだと doc-cover-band / chapter-deck-band / glossary-term-table / fidelity-sync-meta / approval-block / plain-language-term-inline の core chrome が 6 件漏れる) — and assert it forms a bijection with the closure 語彙 SSoT rolemap/srs.census-vocab.yaml の data_components / prose_slots list, flagging with non-zero exit either direction of the symmetric difference: emit ∖ vocab (新部品追加・改名で語彙未更新 = 語彙更新を機械強制) と vocab ∖ emit (部品削除・改名で stale 語彙残存)。 It SHALL fail-closed: emit 抽出が 0 件 (assemble/common 走査破綻) または vocab list が 0 件 (SSoT 欠落/空) を整合と取り違えず FAIL に倒す。 The closure 語彙 SSoT srs.census-vocab.yaml SHALL be a generator-local pack 資産 (新規 file) が集約する『assemble-srs.sh + lib/common.sh が描画する data-component token』∪『data-prose-slot token』の閉集合。 ★M-A 監査補正: 本 SSoT は照会 graph の srs.rolemap.yaml .roles には足さない — verify-graph.sh が roles ⊆ GRAPH_ROLE_ALLOWLIST を hard-FAIL assert するため census 語彙 (data-component token) を .roles へ混ぜると即 FAIL する — ゆえ別 file へ分離し、 verify-graph.sh は <pack>.rolemap.yaml を明示名で開く (rolemap/ を glob しない) ため本 file の追加は verify-graph.sh に副作用ゼロ (非破壊)。 The folio verify-srs command SHALL read this SSoT at startup via pack-level yq (core graph reader lib/graph-common.sh を流用せず = lib/ 無改変), fail-closed (SSoT 不在 / data_components 空 = tool error)。 本 gate は SSoT 配線 + CI 整合 (語彙鮮度) に限る。 ★境界 (§1): 捏造検出の意味権威は ceiling gate J (fidelity-srs) にあるため、 本 gate は語彙鮮度の floor のみを担い、 「全描画要素 ↔ 期待要素の全単射が消費する closure 基盤」(S4/S5) を消費しない。 conformance は verify-census-vocab.sh の lock test (vocab から token を 1 個わざと抜く → assert が赤になる = 非空虚 gate の証明) + genuine (ec / clinic の folio verify-srs floor PASS = SSoT が emit と整合) + graph 非破壊 (verify-graph.sh が census-vocab 追加後も PASS) で固定する。 scope は bd folio-hef.3 (rolemap SSoT 派生 + CI 整合 gate) + taxonomy §5 + bd folio-mzn.2 (語彙鮮度 floor への純化) + bd folio-mzn.3 (census probe carry 配線の除去) で trace。

REQ-VER-030 Event 構成同一性 (construction-integrity・repro-build): folio verify-srs の決定的 floor は生成 SRS を機械 SSoT (contract + prose YAML) から決定的に再組立し、 成果物との byte 同一性を blocking で検査する (非決定 field は footer 生成時刻のみを両辺同一に正規化)。 fabrication-free-by-construction (rules §12) の直接検証形で、 post-build 改変 (転置/複製/削除・decoy・隠蔽/捏造 CSS 注入) を attack 語彙の列挙なしに byte 逸脱として一括検出する (再組立入力の欠落は測定系 error・opt-out (FOLIO_SKIP_REPRO=1) は honest SKIP)。 assembler 自身のバグには盲ゆえ、 contract ↔ 成果物を独立照合する blocking arm と併存する (機構詳細は machine 部)。

REQ-VER-030: WHEN the folio verify-srs deterministic floor runs against a generated SRS presentation, it SHALL re-run the deterministic assembler pipeline (assemble → prose 注入) from the 機械 SSoT inputs (contract YAML + prose YAML) into a scratch path and assert byte-identity between the artifact under verification and the reassembled output, flagging any deviation with non-zero exit as a blocking floor failure (構成同一性 arm = construction-integrity)。 正規化は唯一の非決定 field = footer 生成時刻 (生成: <b>YYYY-MM-DD HH:MM</b> の厳密 pattern) のみを両辺同一の quotient 写像で商する — 両辺を同一関数で写像するため本文へ timestamp 形を注入する攻撃も再組立側との byte 差が残り健全であり、 緩い正規化は差分 masking の穴となるため厳密 pattern に限る。 It SHALL treat 再組立入力の欠落 (contract / prose / assembler 不在) と assembler 自身の非零 exit を gate 判定でなく測定系 tool-integrity error として別軸の非零 exit に倒す (REQ-VER-024 の測定系 error idiom と同型・「入力が無い = PASS」の fail-open を封鎖); 明示 opt-out (FOLIO_SKIP_REPRO=1) 時は honest SKIP (floor 不完全と明示し PASS と詐称しない・gate F の SRS_SKIP_RENDER と同 idiom)。 本 gate は fabrication-free-by-construction (rules §12 の不変条件「構造は SSoT から毎回決定的に再組立し差分編集を介在させない」) の直接検証形であり別建ての決定的安全網ではない; post-build 改変 (contract 由来 token の転置/複製/削除・decoy 要素注入・render 依存の隠蔽/捏造を狙う CSS/HTML 注入) は byte 逸脱として render を要さず一括検出される (partial-enumeration からの構造終端)。 honest scope: 再組立の両辺が同一 assembler を共有するため assembler 自身のバグには盲 — contract ↔ 成果物を独立照合する blocking arm の contract 照合部 (REQ-VER-024 gate A–E,G,H + census-count) を代替せず併存する。 byte 一致 regen の先例は ADR-0036 (glossary ↔ vocabulary regen byte 一致)。 conformance は generator の敵対 suite の repro-build seed (1-byte tamper → FAIL / 生成時刻のみ差 → PASS / 再組立入力欠落 → 測定系 error / 正規化 regex mutant の mutation-kill) で固定する。 scope は rules §12 (fabrication-free-by-construction) + bd folio-mzn.3 (構成同一性 arm の建設・決定的 census (全列挙機構) の構造終端置換) で trace。
